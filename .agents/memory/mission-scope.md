name: Mission scope
description: User-approved scope for the T-Minus Studio mission.
---

Do not include separate Projects or Handshake kit pages.

**Why:** The user said these two pages are not required for the mission and explicitly chose to remove both. The mission focuses on deadline planning, a countdown lock screen, and optional reminders.

**How to apply:** Keep those core features accessible without adding project-management or submission-preparation pages. Preserve existing saved goals when simplifying the interface.

Each core page must have its own clear title and purpose-specific starting screen, even before a goal is saved.

**Why:** The user reported that every page looked the same and explicitly asked to change the titles and UI.

**How to apply:** Do not route all no-goal states to the same generic onboarding screen. Keep Overview, planning, lock-screen design, and reminders visually and functionally distinguishable.

The user selected the Colossal Typographic Landing canvas reference and asked to integrate it faithfully into T-Minus Studio.

**Why:** This is an explicit visual direction, replacing the previous warm green editorial look.

**How to apply:** Preserve the reference's black-and-white presentation, oversized heavy typography, horizontal navigation, subtle grid, and circular primary action. Keep T-Minus branding and actual deadline-planning functions, not the reference agency's identity or placeholder links.

Gemini style references are temporary inspiration inputs, separate from saved wallpaper background photos. Generating options must not change the saved design before the user applies a style.

**Why:** A reference should guide palette and composition without silently replacing a user's existing photo or manual styling. Keeping the reference transient also avoids adding another image to browser-local backups.

**How to apply:** Explain what is sent to Gemini before generation and preserve goal/milestone data. Describe the lightweight action as editable style suggestions. Keep original image generation a separate, clearly labeled opt-in action; neither action may silently replace an existing photo.

Original artwork is stored durably in App Storage, while reference images remain transient inputs. Only an explicit Apply action replaces the saved wallpaper background.

**Why:** The original-artwork feature must coexist with lightweight style suggestions and the existing browser-local goal/photo workflow without silently replacing a user's work or storing more image bytes in browser backups.

**How to apply:** Keep generated image paths rather than image bytes in saved project data. Until account ownership is added, explain that generated artwork uses unlisted, shareable links rather than authenticated private access; do not imply that an unlisted URL makes confidential artwork private.
